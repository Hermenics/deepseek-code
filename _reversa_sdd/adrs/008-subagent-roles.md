# ADR-008: SubAgent Role-Based Permissions

> Status: ACCEPTED  
> Date: 2026 (commit `b022cab`)  
> Confidence: 🟢 CONFIRMED

## Context

SubAgents are spawned by the main agent to perform delegated tasks. Without restrictions, a subagent has access to all tools — including destructive ones like `shell(rm -rf)` or `write_file`. This is dangerous because:
- SubAgent tasks are generated by the LLM, not the user
- SubAgents run with less oversight (no interactive confirmation in some modes)
- A hallucinated task could trigger destructive operations

## Decision

Implement **role-based tool filtering** for subagents with 5 roles:
- `reader`: read-only (files, grep, glob, web_fetch, introspect)
- `reviewer`: even more restricted (files, grep, glob, introspect — no web)
- `writer`: read + write (no shell)
- `executor`: read + write + shell (default)
- `unrestricted`: all tools

Role is **inferred from the task description** using keyword matching. A verification workflow validates subagent outputs before returning to parent.

## Rationale

1. Principle of least privilege — a "search for X" task shouldn't have write access
2. Keyword-based inference is fast and works for ~80% of cases
3. Default to `executor` (not `unrestricted`) ensures subagents can't spawn sub-subagents
4. Verification adds a confidence score to results

## Alternatives Considered

| Alternative | Why Rejected |
|-------------|-------------|
| All subagents get all tools | Violates least privilege, dangerous |
| User explicitly assigns role per spawn | Too much friction, breaks autonomous workflow |
| Static role per agent config | Inflexible — same agent might need different roles for different tasks |
| ML-based role classification | Overkill for 5 categories; keyword matching is sufficient |

## Consequences

- **Positive:** Limits blast radius of hallucinated/malicious subagent tasks
- **Positive:** Reader/reviewer subagents cannot accidentally modify files
- **Positive:** Automatic inference means zero friction for users
- **Negative:** Keyword heuristic can misclassify (e.g., "read the file and fix it" → `executor` because "fix" matches write pattern)
- **Negative:** No way for a subagent to request escalation if it needs more tools mid-task
